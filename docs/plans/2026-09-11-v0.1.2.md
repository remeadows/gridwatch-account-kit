- `getSession()` never rejects; `signIn*` return error strings; `useAccount` returns the same shape as before.
- Version `0.1.2`, tag `v0.1.2`, README pin updated; consumers pin `git+https://github.com/remeadows/gridwatch-account-kit.git#v0.1.2`.

### Task 1: Account bar — no needless re-render, menu a11y, lifecycle guards, failure handling

**Files:**
- Modify: `src/header.ts`, `src/header.css`
- Test: `tests/header.test.ts` (extend)

**Interfaces:**
- Produces (all additive): bar root `role="navigation" aria-label="Account"` (no longer `banner`); chip has `aria-expanded="false"` initially, `aria-controls` = menu id, `aria-haspopup="menu"`; menu has `id`, `role="menu"`, items `role="menuitem"`; Escape (keydown on document while open) and any click outside the bar close the menu; a new `p.gw-account-bar__notice` (hidden unless a sign-out fails) with text `Sign out failed — try again.`; `mountAccountHeader` returns the SAME `MountedHeader` for a second call while a bar is mounted (idempotent), and `unmount()` sets a `disposed` flag so a queued refresh does nothing.
- Behaviour: `refresh()` compares `{ state, handle }` with the last rendered pair and returns without touching the DOM when equal (so an open menu survives `TOKEN_REFRESHED`); a failed `getProfile()` keeps the last known handle for the same user id (falls back to `null` only when there was none); `signOut` failures are caught: `console.warn` + show the notice; a later successful state change hides it.

- [ ] **Step 1: Write the failing tests** — add to `tests/header.test.ts` (use the existing `fakeKit`/`tick`; give `fakeKit` sessions `{ user: { id } }`):
  1. "does not re-render when an auth event carries the same state and handle": mount signed-in, open the menu (click chip), `emit({ user: { id: "u1" } })`, `await tick()`, expect the SAME menu element (keep a reference) still in the DOM and `hidden === false`, and `getProfile` called exactly once more (or zero — assert the menu identity, not the call count, since the profile read happens before the compare; assert `getProfile` was called but the DOM node identity is unchanged).
  2. "closes the menu on Escape and on outside click": open → `document.dispatchEvent(new KeyboardEvent("keydown", { key: "Escape", bubbles: true }))` → hidden; open → `document.body.click()` (a click outside the bar) → hidden; open → click inside the menu container → stays open.
  3. "exposes the menu with ARIA": chip `aria-expanded` is `"false"` before any click and `"true"` after; `aria-controls` equals the menu's `id`; bar `role="navigation"` with `aria-label="Account"`; every item has `role="menuitem"`.
  4. "is idempotent when mounted twice": two `mountAccountHeader(kit)` calls → one `.gw-account-bar` in the DOM and the two return values' `unmount` are the same function.
  5. "drops a refresh queued before unmount": mount, `emit({ user: { id: "u1" } })` then immediately `handle.unmount()` before `tick()`; after `tick()` no `.gw-account-bar` exists and `getProfile` was not called.
  6. "keeps the last known handle when a later profile read fails": signed-in with handle `rusty` rendered; make `getProfile` reject; `emit({ user: { id: "u1" } })`; after tick the chip still reads `rusty` and `data-state` is `signed-in`.
  7. "shows a notice when sign-out fails and clears it on the next successful state": `signOut` rejects → click Sign out → notice visible with the exact text; then `signOut` resolves and `emit(null)` → notice hidden and state `signed-out`.
- [ ] **Step 2: Run to verify they fail** — `npx vitest run tests/header.test.ts`.
- [ ] **Step 3: Implement** in `src/header.ts`: module-level `let mounted: { root: HTMLElement; handle: MountedHeader } | null`; `disposed` flag; `lastRendered: { state, handle } | null` reset on `render`; `render(state, handle)` early-returns when equal to `lastRendered`; menu open/close helpers that also set `aria-expanded`; document-level `keydown` (Escape) and `click` (outside `root`) listeners added on open and removed on close/unmount; `signOut` handlers wrapped in try/catch that shows/hides `p.gw-account-bar__notice`; `refresh()` catch branch for `getProfile` uses `lastRendered?.handle` when the session user id is unchanged. `src/header.css`: `.gw-account-bar__notice { margin: 4px 10px; font-size: 12px; color: var(--gw-bar-warn, #ffb454); } .gw-account-bar__notice[hidden] { display: none; }`.
- [ ] **Step 4: Verify** — `npx vitest run && npm run typecheck && npm run build` (all header tests green; existing ones unchanged).
- [ ] **Step 5: Commit** — `feat(header): stable re-render, menu a11y (Escape/outside-click/ARIA), idempotent mount, unmount guard, resilient profile/sign-out handling` with the trailer. Do not push yet.
